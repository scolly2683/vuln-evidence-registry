Companion to the routing workbench · bulk triage

Sort thousands of scanner rows without touching a host

Paste Qualys, Wiz or Mend results. Each row is classified against what the CVE actually requires to be exploitable — so Java 8 findings that can't run, backup copies, and wrong-artefact detections separate themselves from the ones that matter. Then verify a sample, not everything.

These are proposals, not verdicts. Classification uses only the text in your scanner export, so it can be wrong about any single row. The workflow is: classify in bulk → verify a sample per group with PowerShell → record the verdict for the group, citing the sample as evidence. Never blanket-suppress off text matching alone.

What each classification means

  

    

      
        
NOT APPLICABLEA precondition for exploitation is contradicted by the scan data (e.g. Spring4Shell on JDK 8, or a Spring Boot executable jar rather than a WAR on Tomcat). Verify a sample, then record a not applicable verdict with evidence.

        
DEAD COPYThe artefact is in a backup, crash dump, temp or archive path. Not exploitable — but raise a cleanup finding, don't suppress. Deleting removes the noise permanently.

        
NEEDS CHECKThe scan data doesn't settle it. This is where PowerShell earns its keep — on a sample, not on everything.

        
LIKELY REALPreconditions look satisfied. Route to a fix channel in the routing workbench.

      
    

  

  
Coverage matters: if a group covers only some rows for a CVE, a CVE-level
    suppression would silence the others too — including ones that are genuinely exploitable. The tool
    only offers suppression rows for groups where full coverage applies.
